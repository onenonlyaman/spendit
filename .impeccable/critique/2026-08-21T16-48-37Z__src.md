## Overall Impression

Two products are fighting inside one repo and the wrong one is winning. The engineering is real — natural-language parsing, draft persistence, double-entry accounting, a genuinely good onboarding sandbox. The identity is not: DESIGN.md describes a warm paper ledger that exists nowhere on screen, while an unauthored iOS/Framer glass clone occupies the entire surface. And underneath the aesthetic argument sits a plain functional fact: **a brand-new user cannot save their first transaction, and is shown no error when it fails.**

Biggest opportunity: the paper world is already written. `index.css` has the wax seal, the ruled paper, the stamp animation, the ribbon, all of it. This is not a design problem needing invention — it is a wiring problem. The differentiation is sitting in the stylesheet with zero call sites.

## What's Working

**1. Natural-language capture with live resolution.** `nlpParser.ts` + the preview grid (`QuickAddModal.tsx:261-299`) means "chai 15 cash morning" resolves into description/amount/account/time *before* commit. Trust earned, not requested. Example prompts (`:134-140`) use real Indian daily spend — chai, kirana, cab — not "Coffee $4.50". The one place the specific user shows up in the interface.

**3. The onboarding sandbox.** `OnboardingGuideModal.tsx:147-198` teaches the core interaction by letting the user type into a live parser rather than reading about it. Three-step ceiling respects attention.

## Priority Issues

### [P0] First run is a silent dead end
**What:** `db.ts` seeds no accounts or categories. `QuickAddModal.tsx:92` resolves `effectiveAccountId` to `undefined`, the `NOT NULL REFERENCES accounts(id)` insert rejects, `catch` logs to console only (`:127-129`), and because `setIsQuickAddOpen(false)` sits after the await inside `try`, the modal does not even close.
**Why it matters:** Every new user hits this. The first action the product asks for fails invisibly and forever. The empty state (`DiaryView.tsx:165-184`) never mentions accounts and points at "Log First Entry" — the wrong action.
**Fix:** Seed Cash/UPI/Bank + default categories in the `db.ts` migration. Render an inline error in the modal on catch. Move the close call out of the try. Gate the diary empty state on `accounts.length === 0`.
**Suggested command:** `/impeccable harden` then `/impeccable onboard`

### [P0] "Erase Everything" is one unguarded click
**What:** `SettingsView.tsx:619-627` calls `resetAllData()` straight from the confirm button. No typed confirmation, no forced backup, no counts.
**Why it matters:** Offline-first with no cloud copy — one misclick is unrecoverable by any means. Export JSON/CSV sit three rows above and the dialog never mentions them. Same class of bug: `db.ts:51` `ON DELETE CASCADE` means deleting an account silently destroys every transaction on it, and `AccountsView.tsx:554-573` never says so.
**Fix:** Require typing `ERASE`. Make "Download a backup first" the dialog's primary action. State exact counts being destroyed. Add the cascade warning to account deletion.
**Suggested command:** `/impeccable harden`

### [P1] The seal locks nothing, and the ritual is hidden
**What:** `toggleSealDay` (`FinanceContext.tsx:384`) flips a boolean nothing reads. `TransactionRow.tsx` never checks `sealed` — Edit and Delete stay live on a "sealed, audited" page. The whole closure section defaults collapsed (`DiaryView.tsx:43`) behind a Sparkles icon. **Why it matters:** The product's stated principle is immutable ledger events; the feature dramatizing that principle is theater. And the mindful-reflection half of the value proposition is two clicks below the fold.
**Fix:** Make `sealed` real — disable Edit/Delete on sealed days, require explicit "Break the seal". Default the section open on past days. Replace the pill with the wax medallion + existing stamp animation. Delete the confetti.
**Suggested command:** `/impeccable harden` + `/impeccable delight`

### [P2] Modals are inaccessible; reduced-motion is actively overridden
**What:** Across nine-plus modals: zero `role="dialog"`, zero `aria-modal`, zero focus traps, zero Escape handlers. `App.tsx:82` hard-codes `MotionConfig reducedMotion={performanceMode ? "always" : "never"}` — `"never"` overrides the OS setting (motion's default is `"user"`). Zero `prefers-reduced-motion` or `motion-reduce` anywhere in `src/`. 54 `outline-none` suppressions against exactly 1 `focus-visible` ring in the whole codebase. 8 icon-only buttons with no accessible name (`ChaptersView.tsx:481,487`, `QuickAddModal.tsx:304,360`, `UpdateModal.tsx:232`, `EditTransactionModal.tsx:128`, `SearchView.tsx:142`, `OnboardingGuideModal.tsx:178`). `audioHaptics.ts:9` defaults sound on.
**Why it matters:** PRODUCT.md commits to full keyboard navigation, screen-reader access, and reduced-motion support. All three are broken, and the motion one is an active regression — the app deliberately ignores a stated OS accessibility preference.
**Fix:** One `<Modal>` primitive with `role="dialog" aria-modal="true"`, Escape, focus trap, focus restore; route all nine through it. Change `reducedMotion` to `"user"`. Default haptics off. Pair every `outline-none` with a `focus-visible` ring.
**Suggested command:** `/impeccable audit`

### [P2] The heatmap's color ramp is not a ramp
**What:** `MoneyHeatmap.tsx:26-41` encodes intensity as green → blue → indigo → purple → orange. The legend (`:62-79`) shows four swatches and omits purple entirely.
**Why it matters:** These hues have no perceptual order — nobody can tell whether indigo outranks purple. Pre-attentive magnitude, the entire point of a heatmap, is lost on the primary artifact of the Chapters view. Color-only encoding also fails colorblind users.
**Fix:** Single-hue sequential ramp in archival ochre or ink at increasing density (DESIGN.md's "ink intensity levels"). Keep no-spend days as the distinct `.stamp-nospend` mark, not another hue. Generate the legend from the array that drives the cells.
**Suggested command:** `/impeccable colorize`
